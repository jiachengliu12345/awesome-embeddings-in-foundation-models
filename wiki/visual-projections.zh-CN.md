# 视觉表示如何投影到模型 token 空间

[English](visual-projections.md) · [来源](../SOURCES.zh-CN.md) · [比较](../COMPARISON.zh-CN.md)

![视觉模态路径：图像切块形成向量，加入位置向量并通过视觉编码器，再经归一化和投影映射到语言模型宽度。](../assets/modalities.zh-CN.svg)

*SigLIP 2 图像块投影与 Gemma 4 视觉到语言投影分为两条路径绘制。*

图像进入基础模型时，判断模型是在查找一个已学习向量、从像素计算向量，还是把已有视觉表示投影到另一个模型的宽度。本页中的“投影”指可学习的线性映射。它不是离散词表查找，也不意味着输出一定是用于检索的句子嵌入。

## 从像素计算图像块向量

在 Hugging Face 的 SigLIP 2 实现中，输入已被切分并展平为多个图像块。`Siglip2VisionEmbeddings` 使用 `nn.Linear`，把 $C \times P \times P$ 个值，其中 $C$ 为通道数、$P$ 为图像块边长，再映射到视觉隐藏宽度。随后，模型按图像块位置加上可学习的位置嵌入。代码会根据输入的空间形状调整位置嵌入，并填充到指定序列长度。图像块投影从像素值计算内容表示；位置查表补充空间位置信息。二者是不同的参数对象和计算操作。

这一区分会影响成本。图像块投影会将每个图像块向量乘以一个可学习矩阵，计算量随图像块数量、输入通道数和图像块尺寸变化。位置表的大小取决于所存储的网格；插值和填充也有运行时成本。输入分辨率提高时，图像块数量和编码器计算量可能随之增加。

## 从视觉宽度投影到语言宽度

Gemma 4 的 `encode_vision` 先应用 `mm_pre_projection_norm`（`with_scale=False`），再通过 `mm_input_projection` 从 `vision_proj_dim` 映射到 `embed_dim`。这使视觉表示可以进入语言模型的 token 空间。该向量由视觉编码器计算后再进行变换，而不是依据 token ID 从词表查出。投影包含可学习权重；这条路径的归一化没有可学习缩放参数，仍需执行计算。这与 PLE 不同；PLE 在解码器层内提供按 token 索引的逐层向量。

比较视觉适配模块时，记录输入特征宽度、输出宽度、图像块数量、投影参数量、归一化方式和投影向量的使用位置。还要注明该路径处理所有图像、选定裁剪图，还是采用其他分辨率策略。不能只因模型使用线性层就推断质量或速度。投影可以对齐两个空间的维度，但最终效果取决于编码器、训练数据、分辨率和下游架构。
